# RANCAGE 0.2 Stage 0 — M0.2 Parser & Type Checker Architecture Specification

## 1. Overview & Scope

Milestone M0.2 expands the RANCAGE reference compiler front-end with structural typing, composite collections, nullability tracking, and binding mutability guarantees.

### Scope:
- **Records**: Declarations (`record Point { x: int; y: int; }`), instantiations (`Point { x: 1, y: 2 }`), field access (`p.x`), field mutation (`p.x = 10`).
- **Generic Collections**: `list[T]`, `map[string, V]`, element homogeneity validation, empty collection literal type annotation requirements (`let xs: list[int] = [];`).
- **Nullability**: Nullable types (`T?`), `null` literal, assignability (`null` assignable to `T?`, `T` assignable to `T?`, `T?` NOT assignable to `T`), equality comparison rules (`==` and `!=` between nullable and non-nullable of compatible base type).
- **Target Assignments**: Scalar assignment (`x = e;`), field assignment (`e.f = v;`), index assignment (`e[i] = v;`).
- **Mutability Guarantees**: `const` variable bindings forbid reassignment, field mutation, index mutation, and mutating collection intrinsics (`push`, `pop`, `map_remove`). Non-mutating intrinsics (`len`, `map_has`, `ord`, `chr`, `slice`) are permitted.

## 2. Grammar & Syntax Specification

```ebnf
type_expr ::= primitive_type | record_type | nullable_type | list_type | map_type
primitive_type ::= "int" | "float" | "bool" | "string"
record_type    ::= IDENT
nullable_type  ::= (primitive_type | record_type | list_type | map_type) "?"
list_type      ::= "list" "[" type_expr "]"
map_type       ::= "map" "[" "string" "," type_expr "]"

record_decl    ::= "record" IDENT "{" (IDENT ":" type_expr ";")* "}"
record_init    ::= IDENT "{" (IDENT ":" expr ("," IDENT ":" expr)* ","?)? "}"
map_literal    ::= "{" (expr ":" expr ("," expr ":" expr)* ","?)? "}"
list_literal   ::= "[" (expr ("," expr)* ","?)? "]"

target_assign  ::= primary "=" expr ";"
                 | primary "." IDENT "=" expr ";"
                 | primary "[" expr "]" "=" expr ";"
```

### Recursion Depth Limit (Remediation Finding 3)
To prevent compiler stack exhaustion and unhandled host Python `RecursionError` on deeply nested type annotations (e.g., `list[list[...]]`), `Parser.type_expr` enforces an explicit recursion depth limit of **64**. Exceeding this limit immediately raises `RancageSyntaxError("Batas kedalaman tipe terlampaui", line, col)`.

## 3. Namespace Architecture (Finding 4 Resolution)

Functions and records coexist in distinct namespaces:
- **Functions** occupy callable namespace (`functions: dict[str, Function]`).
- **Records** occupy nominal type definition namespace (`records: dict[str, RecordDecl]`).

### Rationale:
Record instantiation in RANCAGE uses braced struct syntax (`Point { x: 1, y: 2 }`), distinct from function call parentheses (`Point(1, 2)`). This syntactic distinction eliminates runtime ambiguity between function invocations and record instantiations. A record and a function sharing the same identifier is permitted syntactically without collision, while type annotations resolve identifiers against the record namespace.

## 4. Static Type System & Invariants

1. **Subtyping & Assignability**:
   - For all types `T`, `T` is assignable to `T`.
   - `null` is assignable to `T?` for any base type `T`.
   - `T` is assignable to `T?`.
   - `T?` is **not** assignable to `T` without explicit narrowing/guard.
   - Distinct records `A` and `B` are invariant and mutually unassignable even if structurally identical.

2. **Collection Invariants**:
   - `list[T]` requires all elements to unify to `T`.
   - `map[string, V]` requires keys to be `string` and values to unify to `V`.
   - Empty collection literals (`[]`, `{}`) require explicit contextual typing via variable annotation or expected parameter type.

3. **Target Immutability & Const Protection (Remediation Finding 2)**:
   - `const x: T = v;` creates an immutable root binding `x`.
   - Reassignment statements targeting `x`, fields rooted in `x` (`x.f = v`), or indices rooted in `x` (`x[i] = v`) are rejected with `RancageTypeError("Konstanta 'x' tidak bisa diubah")`.
   - Mutating intrinsic calls (`push(x, v)`, `pop(x)`, `map_remove(x, k)`) where root receiver is in `consts` are rejected with `RancageTypeError("Konstanta 'x' tidak bisa diubah")`.
   - Pure intrinsics (`len(x)`, `map_has(x, k)`, `ord`, `chr`, `slice`) remain allowed on `const` targets.

4. **Intrinsics Signatures**:
   - `len(list[T] | map[string, V] | string) -> int` (Pure)
   - `push(list[T], T) -> void` (Mutating, requires non-const target)
   - `pop(list[T]) -> T` (Mutating, requires non-const target)
   - `map_has(map[string, V], string) -> bool` (Pure)
   - `map_remove(map[string, V], string) -> bool` (Mutating, requires non-const target)
   - `ord(string) -> int` (Pure)
   - `chr(int) -> string` (Pure)
   - `slice(string, int, int) -> string` (Pure)
