# RANCAGE 0.2 Stage 0 — M0.5 Integration & Baseline Architecture Specification

## 1. Executive Summary & Stage 0 Baseline

Milestone M0.5 consolidates the end-to-end integration of the RANCAGE Stage 0 reference implementation across all components:
- **Lexer**: [`Lexer`](src/rancage/lexer.py:22) in [`src/rancage/lexer.py`](src/rancage/lexer.py)
- **Parser**: [`Parser`](src/rancage/parser.py:9) in [`src/rancage/parser.py`](src/rancage/parser.py)
- **Type Checker**: [`TypeChecker`](src/rancage/typesys.py:20) in [`src/rancage/typesys.py`](src/rancage/typesys.py)
- **Compiler**: [`Compiler`](src/rancage/compiler.py:15) in [`src/rancage/compiler.py`](src/rancage/compiler.py)
- **Virtual Machine**: [`VirtualMachine`](src/rancage/vm.py:112) in [`src/rancage/vm.py`](src/rancage/vm.py)
- **CLI**: [`main()`](src/rancage/cli.py:42) in [`src/rancage/cli.py`](src/rancage/cli.py)

Stage 0 establishes a verified, self-contained reference toolchain in pure Python 3.10+ standard library. It provides nominal records, generic collections (`list[T]`, `map[string, V]`), Unicode strings, nullable types (`T?`), signed 64-bit integer arithmetic, defensive bytecode validation, cycle-safe value formatting, deterministic memory allocation accounting, and sandboxed bytecode execution.

## 2. Pipeline Integration Architecture

The compilation and execution pipeline follows a strict, single-pass forward flow:

```
Source (.cage)
      │
      ▼
┌──────────────┐
│    Lexer     │  Token stream with file, line, and column spans
└──────┬───────┘
      │
      ▼
┌──────────────┐
│    Parser    │  Recursive-descent & Pratt expression parsing into AST Program
└──────┬───────┘
      │
      ▼
┌──────────────┐
│ TypeChecker  │  Validates nominal records, collections, nullability;
└──────┬───────┘  annotates Expr.inferred_type
      │
      ▼
┌──────────────┐
│   Compiler   │  Lowers typed AST into portable RANCAGE-IR 0.2 bytecode
└──────┬───────┘
      │
      ▼
┌──────────────┐
│ Bytecode Val │  VirtualMachine._validate() statically inspects opcodes,
└──────┬───────┘  arities, call targets, record schemas, and int64 constants
      │
      ▼
┌──────────────┐
│  VM Runtime  │  Sandboxed execution bounded by step, depth, and allocation budgets
└──────────────┘
```

### 2.1 Component Contracts

1. **Lexer -> Parser**:
   - [`Lexer.tokenize()`](src/rancage/lexer.py:49) converts UTF-8 source text into a list of [`Token`](src/rancage/lexer.py:6) objects.
   - Raises [`RancageSyntaxError`](src/rancage/lexer.py:12) with 1-based line and column offsets upon invalid characters, unterminated strings, or malformed numbers.

2. **Parser -> TypeChecker**:
   - [`Parser.parse()`](src/rancage/parser.py:82) constructs an abstract syntax tree rooted at [`Program`](src/rancage/ast.py:24), comprising [`RecordDecl`](src/rancage/ast.py:18) and [`Function`](src/rancage/ast.py:36) definitions.
   - Pratt parsing deterministically resolves operator precedence and associativity.

3. **TypeChecker -> Compiler**:
   - [`TypeChecker.check()`](src/rancage/typesys.py:59) performs two-pass record registration, function signature registration, and statement-level type checking.
   - Ensures exhaustive returns for non-void functions, constant immutability, collection type homogeneity, and null safety.
   - Annotates each expression AST node with its resolved `inferred_type: str`.
   - Raises [`RancageTypeError`](src/rancage/typesys.py:10) on semantic violations.

4. **Compiler -> VM**:
   - [`Compiler.compile()`](src/rancage/compiler.py:19) lowers typed AST structures into JSON-serializable RANCAGE-IR 0.2 bytecode dictionaries.
   - Emits structured metadata: `format: "RANCAGE-IR"`, `version: "0.2"`, `entry: "main"`, `records: dict[str, list[str]]`, and `functions: dict[str, dict]`.
   - Expression statements consistently emit `POP` instructions, ensuring clean operand stack balances.

5. **VM Bytecode Validation -> Execution**:
   - [`VirtualMachine._validate()`](src/rancage/vm.py:145) statically validates untrusted IR before running.
   - Confirms valid opcode names, instruction arities, known function jump targets, known intrinsic names and arities, record schema definitions, field permutations on `MAKE_RECORD`, and signed 64-bit integer literal bounds.
   - [`VirtualMachine.run()`](src/rancage/vm.py:246) executes instructions in a hermetic evaluation environment.

## 3. Intermediate Representation Hierarchy & Compatibility

The runtime execution environment supports three distinct IR format tiers:

| Tier | Format String | Version String | Status | Emission / Parsing Rules |
|---|---|---|---|---|
| **Primary Active** | `"RANCAGE-IR"` | `"0.2"` | Active Default | Emitted by [`Compiler`](src/rancage/compiler.py:15); full Stage 0 feature support (records, collections, intrinsics). |
| **Baseline Historical**| `"RANCAGE-IR"` | `"0.1"` | Backward Compatible | Supported by [`VirtualMachine`](src/rancage/vm.py:112); executes 0.1 flat bytecode programs. |
| **Legacy Read-Only** | `"NOVA-IR"` | `"0.1"` | Backward Compatible | Supported by [`VirtualMachine`](src/rancage/vm.py:112); read-only migration format for historical payloads. |

Bytecode validation allows `"RANCAGE-IR"` versions `"0.1"` and `"0.2"`, as well as `"NOVA-IR"` version `"0.1"`. Any unsupported format identifier or version string is rejected at initialization time with a [`RancageRuntimeError`](src/rancage/vm.py:11).

## 4. Runtime Execution Model, Value Model & Resource Bounds

### 4.1 Value Representation

| Type | Runtime Class | Isolation & Limits |
|---|---|---|
| `int` | Python `int` | Signed 64-bit bounds: `[-9223372036854775808, 9223372036854775807]`. Checked on creation and arithmetic. |
| `float` | Python `float` | Finite IEEE 754 floating-point numbers. Rejects `NaN` and `Infinity`. |
| `bool` | Python `bool` | Strictly `True` or `False`. |
| `string` | Python `str` | Immutable Unicode scalar sequence; capped at `MAX_STRING_LENGTH = 1_000_000`. |
| `null` | Python `None` | Null reference; dereference raises [`RancageRuntimeError`](src/rancage/vm.py:11). |
| `list[T]` | Python `list` | Homogeneous sequence; capped at `MAX_COLLECTION_SIZE = 100_000`. |
| `map[string, V]` | Python `dict` | Hash map with string keys; missing keys raise [`RancageRuntimeError`](src/rancage/vm.py:11). Capped at `MAX_COLLECTION_SIZE = 100_000`. |
| `record` | [`RecordInstance`](src/rancage/vm.py:69) | Nominal product instance holding `name: str` and `fields: dict[str, Any]`. |

### 4.2 Guardrail Limits and Resource Controls

All resource limits are codified centrally in [`src/rancage/vm.py`](src/rancage/vm.py):

| Constant | Value | Enforcement Point | Error Message |
|---|---|---|---|
| `MAX_DEPTH` | `128` | [`VirtualMachine._call()`](src/rancage/vm.py:347) | `"Batas kedalaman pemanggilan fungsi terlampaui"` |
| `MAX_STEPS` | `1_000_000` | Instruction loop in [`VirtualMachine._call()`](src/rancage/vm.py:347) | `"Batas instruksi program terlampaui"` |
| `MAX_ALLOCATED_UNITS` | `2_000_000` | [`VirtualMachine._charge_allocation()`](src/rancage/vm.py:130) | `"Batas alokasi memori program terlampaui"` |
| `MAX_COLLECTION_SIZE` | `100_000` | `MAKE_LIST`, `MAKE_MAP`, `push` | `"Ukuran koleksi melebihi batas maksimum (100000)"` |
| `MAX_STRING_LENGTH` | `1_000_000` | `+` (string concat), `slice`, `chr` | `"Panjang string melebihi batas maksimum (1000000)"` |
| `MAX_FORMAT_DEPTH` | `32` | [`format_value()`](src/rancage/vm.py:28) | Truncates nested printing to `{...}` or `[...]` |

## 5. Deterministic Allocation Accounting Specification

Cumulative allocation accounting prevents heap exhaustion from repeated small allocations in loops. The virtual machine tracks `self.allocated_units: int` across the lifetime of the program execution:

Allocation units represent deterministic abstract semantic cost counters, not physical host RAM bytes or live operating system heap measurements.


| Operation | Unit Charge Calculation | Contractual Invariant |
|---|---|---|
| `MAKE_LIST` | `count + 1` | Bounded by `MAX_COLLECTION_SIZE` |
| `MAKE_MAP` | `count + 1` | `count` is key-value pair count; bounded by `MAX_COLLECTION_SIZE` |
| `MAKE_RECORD` | `n + 1` | `n = len(fields)` |
| `MAP_SET` | `1` or `0` | Charged `1` unit on new key insertion; `0` units on key overwrite |
| `push` intrinsic | `1` | Charged `1` unit for appended list slot |
| `chr` intrinsic | `1` | Charged `1` unit for single character string creation |
| `STRING_GET` | `1` | Charged `1` unit for single character string slice |
| String `ADD` (`+`) | `len(a) + len(b)` | Charged for total length of resulting string |
| `slice` intrinsic | `end - start` | Charged for normalized length of extracted substring |

If any allocation causes `self.allocated_units > self.max_allocated_units`, [`VirtualMachine._charge_allocation()`](src/rancage/vm.py:130) raises [`RancageRuntimeError("Batas alokasi memori program terlampaui")`](src/rancage/vm.py:134).

## 6. Defensive Bytecode Validation Architecture

[`VirtualMachine._validate()`](src/rancage/vm.py:145) performs pre-execution validation on untrusted IR dictionaries:
1. **Schema Check**: Validates `format`, `version`, `entry`, `functions`, and optional `records`.
2. **Entry Function**: Verifies `entry` function exists in `functions` and takes zero arguments.
3. **Opcode Whitelist**: Confirms every instruction opcode belongs to the supported 33-opcode set.
4. **Instruction Arity**: Checks operand list lengths per opcode schema.
5. **Call Targets**:
   - `CALL`: Pre-execution arity check validates `argc == len(fn_params)` for user functions.
   - Built-in Intrinsics: Dispatches only known names with exact argument counts.
6. **Record Verification**: Verifies record existence and requires `MAKE_RECORD` field names to be a valid permutation of declared record fields.
7. **Numeric Boundary Check**: Verifies integer constants on `PUSH` satisfy signed 64-bit boundaries `[MIN_INT64, MAX_INT64]`.

## 7. Standard Intrinsics & Cycle-Safe Output Semantics

Stage 0 standard intrinsics provide fundamental operations without host exposure:
- `len(val)`: Returns length of `string`, `list`, or `map`.
- `push(list, elem)`: Appends element to list; returns `None`.
- `pop(list)`: Removes and returns last element; raises error on empty list.
- `ord(str)`: Returns Unicode code point of single-character string.
- `chr(int)`: Returns single-character string from Unicode code point.
- `slice(str, start, len)`: Returns substring with bounds clamping.
- `map_has(map, key)`: Returns `bool` indicating presence of key.
- `map_remove(map, key)`: Removes key from map; returns `True` if removed, `False` if not found.
- `print(val)`: Formats and outputs value via cycle-safe [`format_value()`](src/rancage/vm.py:28).

Cycle-safety tracks active object IDs using Python's `seen: set[int]`. Circular structures print `<cycle>`, and structures nested beyond `MAX_FORMAT_DEPTH = 32` print `{...}` or `[...]`, preventing stack recursion errors.

## 8. CLI Tooling Pipeline

The reference CLI tool [`cage`](src/rancage/cli.py) provides four commands:
- `cage check <source.cage>`: Validates syntax and static types; reports `OK: <source> valid (RANCAGE <__version__>)`.
- `cage build <source.cage> [-o output.rcb]`: Compiles source into formatted RANCAGE-IR 0.2 JSON bytecode.
- `cage run <program.cage|program.rcb> [--max-steps N]`: Executes source or bytecode within the virtual machine.
- `cage targets`: Displays target compilation backend registry.

CLI findings disposition:
- Hardcoded version diagnostic in `check` command is resolved to use package `__version__`.
- Additional runtime budget flags (`--max-depth`, `--max-alloc`, `--max-collection-size`, `--max-string-len`) are deferred to Stage 1 CLI enhancement.

## 9. Security Boundaries & Threat Model

The RANCAGE Stage 0 runtime enforces an in-process language sandbox:
- **Zero Host Exposure**: No host OS filesystem, socket, network, process execution, or environment variable access instructions exist.
- **Hermetic VM**: Bytecode cannot invoke arbitrary Python built-ins, `import`, `eval()`, or `exec()`.
- **Resource Exhaustion Defenses**: Step limit, call depth limit, memory allocation budget, collection size limit, and string length limit guarantee deterministic termination on untrusted input.
- **Explicit Boundary**: The VM sandbox protects against untrusted RANCAGE bytecode programs consuming host memory or CPU within the Python process. It is not an OS-level kernel boundary against malicious host binary tampering.
